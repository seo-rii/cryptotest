## 1. Caesar와 Vigenère의 원리 및 빈도 차이

알파벳을 `A=0, ..., Z=25`로 나타내자.

Caesar cipher는 모든 위치에 같은 shift `k`를 적용하는 단일 알파벳 치환이다.

```text
C_i = P_i + k (mod 26)
P_i = C_i - k (mod 26)
```

따라서 평문에서 자주 나타나는 문자는 암호문에서도 똑같이 자주 나타나되, 빈도표의 이름만 일정하게 이동한다. 영어의 불균등한 단문자 빈도와 IC가 그대로 보존되고 key 공간도 26개뿐이다.

Vigenère cipher는 key `K_0 ... K_(r-1)`를 반복한다.

```text
C_i = P_i + K_(i mod r) (mod 26)
```

전체 암호문은 서로 다른 shift를 사용한 `r`개 부분열의 혼합이다. 여러 이동 빈도가 섞이므로 전체 단문자 분포는 Caesar보다 평탄해지고 IC는 무작위 알파벳의 `1/26 ≈ 0.0385`에 가까워진다. 반면 `i mod r`가 같은 문자끼리 모으면 각 부분열은 다시 Caesar cipher이므로 영어에 가까운 IC와 빈도 분포가 나타난다.

중요한 포함 관계도 있다. 길이 1인 Vigenère key는 수학적으로 Caesar cipher와 완전히 같다. 이 사실은 마지막 AI 분류 문항의 식별 가능성에 직접 영향을 준다.

## 2. IC 계산과 암호 종류 판정

길이 `N`, 문자별 출현 횟수 `n_i`에 대해 다음을 계산했다.

```text
IC = Σ_i n_i(n_i - 1) / (N(N - 1))
```

두 파일에서 A~Z 이외 문자를 제외하면 모두 길이 `19,897`이다.

```text
ciphertexts1: 0.067638  → 소수 넷째 자리에서 반올림: 0.068
ciphertexts2: 0.043972  → 소수 넷째 자리에서 반올림: 0.044
```

`ciphertexts1`의 값은 영어 자연어의 약 `0.065`와 가깝고, `ciphertexts2`는 균등분포 값에 훨씬 가깝다. 따라서 각각 Caesar, Vigenère로 판정한다.

## 4. Vigenère key와 평문 복원

### 줄 경계 처리

원본 파일에는 157개 줄이 있고 두 파일의 줄 길이가 정확히 같다. `ciphertexts2`의 암호화 구현은 새 줄마다 key index를 0으로 초기화한다. 따라서 줄을 제거한 뒤 하나의 연속 암호문으로 취급하면 key phase가 어긋난다. 반복거리와 부분열은 줄 경계를 넘지 않게 계산해야 한다.

복원한 `KLVOJ`를 두 방식으로 적용해 Caesar 쪽에서 얻은 평문과 문자별로
대조하면 차이가 수치로도 명확하다.

```text
line-reset 방식: 19,897 / 19,897 문자 일치
연속 key 방식:     3,076 / 19,897 문자 일치
```

### 4-가. Kasiski 반복거리

각 줄 안에서 반복되는 5-gram의 인접 출현 간격을 모았다. 총 261개 중 후보 길이로 나누어떨어지는 수는 다음과 같다.

| 후보 길이 | 나누어떨어지는 거리 | 비율 |
|---:|---:|---:|
| 2 | 178 / 261 | 68.199% |
| 3 | 60 / 261 | 22.989% |
| 4 | 56 / 261 | 21.456% |
| **5** | **260 / 261** | **99.617%** |

전체 거리의 단순 GCD는 우연한 반복 하나 때문에 1이지만, 반복거리의 거의 전부가 5의 배수라는 강한 신호가 있다. 문제의 `|k| ≤ 5` 조건까지 적용하면 key 길이는 5다.

### 4-나. 위치별 카이제곱

모든 줄의 `position mod 5`가 같은 문자들을 합쳐 다섯 부분열을 만들고, 각 부분열에서 26개 Caesar shift의 카이제곱 값을 비교했다.

| key 위치 | 부분열 길이 | 최소 shift | 문자 | 최소 χ² | 차순위 χ² |
|---:|---:|---:|---:|---:|---:|
| 0 | 4047 | 10 | K | 222.518 | 14602.574 |
| 1 | 4016 | 11 | L | 179.146 | 14608.405 |
| 2 | 3975 | 21 | V | 406.928 | 14335.184 |
| 3 | 3942 | 14 | O | 231.591 | 12991.922 |
| 4 | 3917 | 9 | J | 165.249 | 12719.077 |

각 열의 최솟값이 명확하므로 key는 `KLVOJ`다. 이 key로 전체 파일을 줄마다 처음부터 적용하면 Caesar 쪽에서 얻은 평문과 완전히 일치한다.

## 5. 학습 기반 분류기

### 데이터와 누출 없는 분할

라벨은 앞 절의 분석 결과로 정한다.

- `ciphertexts1.txt`의 줄: Caesar, label 0
- `ciphertexts2.txt`의 대응 줄: Vigenère, label 1
- 통계량이 지나치게 불안정한 50자 미만 줄은 제외
- 원래 줄 번호가 5의 배수인 쌍은 test, 나머지는 train

두 암호문은 같은 평문을 사용한다. 한쪽의 특정 평문 줄이 train이고 다른 쪽의 같은 줄이 test이면 내용 누출이 생기므로, 반드시 대응하는 두 줄을 함께 train 또는 test로 보냈다. 최종 표본 수는 train 218개, test 58개이며 두 class가 균형을 이룬다.

### Feature 설계

각 줄에서 다음 18개 실수 feature를 계산한다.

1. 전체 IC
2. Shannon entropy
3. 26개 Caesar shift 중 최소 정규화 χ²
4. 최빈 문자 비율
5. 거리 1~10의 문자 일치율 10개
6. 후보 period 2~5로 나눈 열들의 가중 평균 IC 4개

모두 알파벳 전체를 일정하게 이동해도 변하지 않는다. 따라서 특정 Caesar
shift `6`은 feature에서 제거된다. 그러나 이 불변성만으로 일반화를
보장하지는 않는다. 고정된 Vigenère period `5`, 고정 key `KLVOJ`, 대한민국
헌법 영문 corpus의 통계에 특화될 가능성은 그대로 남아 있다.

### 모델과 학습

외부 패키지 없이 binary logistic regression을 구현했다. train set의 평균과 표준편차로 각 feature를 표준화하고, 다음 L2 정규화 교차엔트로피를 full-batch gradient descent로 최소화한다.

```text
L(w) = -mean(y log p + (1-y) log(1-p)) + 0.01/2 * ||w||²
p = sigmoid(w₀ + w·x)
```

- epoch: 1,500
- learning rate: 0.1
- 판단 threshold: `P(Vigenère) ≥ 0.5`
- 난수 사용 없음

동일 corpus와 동일 암호화 key 안에서 대응 평문 쌍을 함께 분리한
`paired line holdout` 결과는 다음과 같다.

```text
                  predicted Caesar   predicted Vigenere
actual Caesar             29                  0
actual Vigenere            0                 29

accuracy = 58 / 58 = 100.000%
```

이 수치는 같은 두 파일에서 보지 않은 줄을 분류한 결과이지, 새로운 문서,
새로운 Vigenère 길이 또는 train과 다른 key에 대한 일반화 성능이 아니다.
외부 corpus가 배포 데이터에 포함되어 있지 않아 그런 실험 결과를
만들어 적지 않았다. 더 강한 평가는 별도의 영어 corpus를 train/test
사이에서 분리하고, Caesar의 26개 무작위 shift 및 길이 2~5의 무작위
Vigenère key도 서로 겹치지 않게 생성한 뒤 길이별 confusion matrix를
보고해야 한다.

### 관측 가능한 구조와 출제 의도 추정의 분리

문제는 네 문장이 Caesar와 Vigenère의 혼합이라고 표현하지만, 배포된 암호문에는 숨은 암호화 함수의 이름을 결정할 정보가 없다.

- 1번에서 각 문자를 4만큼 더하면 정확히 2번이다.
- 3번에서 각 문자를 22만큼 더하면 정확히 4번이다.
- 네 문장 모두 단일 고정 shift로 완전한 영어 평문이 된다.
- 길이 1인 Vigenère key는 동일한 shift의 Caesar cipher와 같은 함수다.

따라서 예를 들어 2번을 “Vigenère key `K`로 만들었다”와 “Caesar shift
10으로 만들었다”는 가설은 암호문만으로 구별할 수 없다. 관측 가능한
암호 구조에 대한 답은 다음과 같다.

```text
1: Caesar-like (shift 6)
2: Caesar-like (shift 10)
3: Caesar-like (shift 10)
4: Caesar-like (shift 6)
```

다만 문제는 각 문장을 두 이름 중 하나로 직접 분류하라고 요구한다. 복원된
긴 파일의 Caesar key가 `6`이고 Vigenère key `KLVOJ`의 첫 글자 `K`가
shift `10`이라는 점을 생성기 단서로 해석하면, 출제 의도상 예상 라벨은
다음일 가능성이 높다.

```text
1: Caesar
2: Vigenère
3: Vigenère
4: Caesar
```

이 두 번째 목록은 암호문에서 증명한 결과가 아니라, Vigenère 표본이 길이
1 key `K`를 사용했거나 구현상 첫 key 문자만 반복했다는 생성 과정의
추정이다. 제출에는 채점 대상의 직접 답을 빠뜨리지 않도록 두 결과와 그
논리적 지위를 함께 적는다.
