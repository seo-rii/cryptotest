# 7. 소인수분해 - RSA 부분 비트 유출

## 문제

2048비트 RSA 공개키 `N = pq`, 공개 지수 `e = 65537`, 암호문 `ct`가 주어진다. 1024비트 소수 `p`에 대해서는 `MASK`와 `p & MASK`도 공개된다. `MASK`의 비트가 1인 위치에서는 `p`의 해당 비트를 알 수 있다.

목표는 유출된 비트를 이용해 `p`, `q`를 복원하고 textbook RSA 암호문을 복호화하는 것이다.

## 결과와 성공 경로

최종 평문은 다음과 같다.

```text
FLAG{d1rty_b1t_l34k_c0pp3rsm1th_m33ts_str4t3gy}
```

제출용 성공 경로만 먼저 요약하면 다음 여덟 단계다.

1. 양끝의 미지 4비트씩을 `cid=0..255`로 전수조사한다.
2. 나머지 미지 영역을 `X=2^155`, `Y=2^230`인 두 연속 변수로 완화한다.
3. `p=C+2^265*x+2^600*y`에서 `p | N`인 unknown-divisor 선형식을 만든다.
4. `m=17,t=5`의 Herrmann--May shift 171개를 만들고 FLATTER로 감축한다.
5. 짧은 12개 행을 정수 보조 다항식으로 되돌린다.
6. 약 30비트 소수체의 modular resultant/GCD로 공통근을 얻고 CRT로 합친다.
7. blind scan에서 `cid=155`가 factor를 내며, `p*q=N`과 mask를 확인한다.
8. textbook RSA를 복호화하고 다시 `m^e mod N == ct`인지 검사한다.

격자 감축과 12개 행 선택, modular resultant 추출은 heuristic이다.
따라서 factor를 찾은 branch의 **soundness**는 나눗셈·mask·RSA 재암호화로
확보하지만, `no_recovery` branch에 근이 없다는 **completeness**는 주장하지
않는다. 아래 긴 실패 기록은 최종 공격과 분리한 연구 부록이며, 제출 경로의
근거로 사용하지 않는다.

## 배경지식

### 부분 키 노출과 작은 근

RSA의 소인수 일부가 충분히 알려지면 미지 부분을 변수로 놓고 다음 나눗셈 조건을 이용할 수 있다.

```text
p(x, y) | N
```

이는 실제 근에서 `p(x, y) = 0 mod p`인 작은 근 문제다. Coppersmith 및 Herrmann--May 계열 공격은 이 합동식을 만족하는 다항식의 배수들을 격자에 넣고 감축하여, 실제 작은 근에서 정수 0이 되는 보조 다항식들을 얻는다.

### 마스크 구조

`MASK`를 LSB=0 기준으로 파싱하면 1024비트 중 672비트를 알고 352비트를 모른다. 미지 구간은 다음 일곱 개다.

```text
150..153    4 bits
265..348   84 bits
362..419   58 bits
600..668   69 bits
682..768   87 bits
784..829   46 bits
920..923    4 bits
```

### 직접 탐색과 실패한 전략

미지 비트 352개의 전수조사는 `2^352` 경우라 불가능하다. 그래서 비트벡터, carry 제약, Hensel lifting, 여러 형태의 작은 근 격자, SAT와 Coppersmith의 하이브리드를 차례로 시험했다. 아래에서 “실패”는 방법 자체가 틀렸다는 뜻이 아니라, 기록한 변수 분할과 파라미터로 검증된 factor를 얻지 못했다는 뜻이다. 특히 `UNSAT`/`INFEASIBLE`, 정리의 bound와 안전 margin을 통과한 `no-root`, heuristic `no-root`, `UNKNOWN`/timeout을 구분했다. 이 인스턴스에서 hard 조건을 끝까지 만족한 small-root 배제는 low600뿐이며 q-gap은 beta 경계 때문에 휴리스틱이다. heuristic `no-root`와 `UNKNOWN`/timeout은 branch 제거 증거로 사용하지 않았다.

#### 352비트 전수조사

마스크가 누출하지 않은 일곱 구간을 그대로 열거하면 후보가 `2^352 ≈ 9.17×10^105`개다. 가령 초당 `10^12`개 후보를 검사한다고 비현실적으로 낙관해도 약 `2.9×10^86`년이 걸린다. 가장 작은 내부 구간 `[784,830)`만 열거해도 `2^46 ≈ 7.0×10^13`개이며, 그 값만 정해져서는 나머지 구간이 결정되지 않으므로 독립적인 완전 탐색으로 이어지지 않는다.

반면 양끝의 `[150,154)`와 `[920,924)`는 합쳐서 8비트뿐이다. 이 둘만 열거하면 `2^8=256`개이므로, 전수조사를 완전히 버리는 대신 작은 edge 선택에만 적용하고 큰 내부 구간은 격자로 넘기는 것이 현실적인 경계였다.

#### 전체 2048비트 곱셈 SMT

가장 직접적인 모델은 1024비트 `p`, `q`를 비트벡터로 두고 누출된 `p` 비트, 그로부터 유도한 `q`의 하위·상위 비트, `p*q=N`을 동시에 강제하는 것이다. full-size Z3 실행에서는 `p` 672비트와 `q` 250비트(하위 150비트와 상위 prefix 100비트)를 고정했지만 약 63초 뒤 `UNKNOWN`으로 끝났다. 이는 해가 없다는 뜻이 아니라 2048비트 곱셈의 carry 관계를 제한 시간 안에 전파하지 못했다는 뜻이므로, 어떤 branch도 제거할 수 없었다.

병목은 단순히 변수 개수만이 아니었다. 흩어진 미지 구간 때문에 한 구간에서 정해진 부분곱과 carry가 멀리 떨어진 known-bit 섬까지 전달되어야 했다. 이 장거리 의존성을 가진 모델이 63초 안에 완전한 factor나 `UNSAT`에 도달하지 못했으므로, 정답 후보를 직접 찾거나 안전하게 줄이는 도구가 되지 못했다.

#### 하위 곱셈만 정확히 표현한 CP-SAT

전체 곱셈 대신 `p*q=N`의 하위 `T`비트만 limb와 carry로 정확히 표현하는 exact-tail CP-SAT도 만들었다. `T=928`에서 상단 edge nibble을 자유 변수로 둔 모델은 `p` unknown Bool 348개, `q` fixed bit 269개, `q` variable limb 42개, low-low product 변수 888개를 가졌고 마지막 carry가 0이라는 조건까지 강제했다.

`x0=0..15`, `x7` 자유, seed 7의 16회 얕은 탐색은 총 195.58초 동안 247,599 branches와 14,095 conflicts를 만들었지만 모두 `UNKNOWN`이었다. `q`를 265비트까지 low-lift한 변형은 172.09초, 141,533 branches, 4,459 conflicts로 계산량은 줄었지만 판정은 같았다. 이어 seed `7,13,23`을 사용한 48회 30초 탐색도 총 1,504.11초, 852,177 branches, 77,505 conflicts 뒤 전부 `UNKNOWN`이었다.

CP-SAT에서는 검증된 `FEASIBLE` 또는 `OPTIMAL` assignment만 해 후보가 되고 `INFEASIBLE`만 branch 폐기 증거가 된다. 관측된 `UNKNOWN`은 어느 쪽도 아니었다. exact-tail은 전체 edge 공간을 16개 모델로 덮을 수 있다는 장점은 있었지만, 실행 시간을 늘려도 판정력이 생기지 않아 간헐적인 direct-hit 검사로만 남겼다.

#### Hensel-prefix 분기

`p*q ≡ N (mod 2^k)`를 만족하는 low-bit prefix를 한 비트씩 lifting하고, 새로 만나는 누출 `p` 비트에서 모순을 검사하는 방법도 시험했다. top 16 후보의 `k=370,390,410` 검사는 52.68초가 걸렸다. 370비트에서는 `SAT` 15개와 `UNKNOWN` 1개였지만, 390비트와 410비트에서는 16개 모두 `UNKNOWN`이었다. top 4를 `k=430,500,600`에서 검사한 실행도 70.64초 뒤 모두 `UNKNOWN`이었고, 한 후보의 `k=600` 제한을 30초로 늘려도 결과는 같았다.

이 모델에서 `UNSAT`은 해당 cube가 그 modulus까지도 곱셈식을 만족하지 못한다는 정확한 배제 증거다. 반면 `SAT`은 현재 prefix와 carry가 모순 없이 이어진다는 뜻일 뿐 완전한 1024비트 소인수가 존재한다는 뜻이 아니며, `UNKNOWN`은 아무 결론도 주지 않는다. 긴 미지 구간에서 다음 known-bit 섬에 닿기 전에 상태 공간이 커졌고 유용한 `UNSAT`이 나오지 않아, Hensel 결과는 sanity check나 약한 순위 특성으로만 사용했다.

#### exact 다변수 Herrmann--May

처음에는 일곱 미지 구간 `[4,84,58,69,87,46,4]`을 그대로 일곱 변수로 둬 마스크 구조를 모두 보존하려 했다. 낮은 `m,t`에서는 factor를 얻지 못했고, `m=4,t=1`도 후보 하나에 약 340초가 걸린 뒤 실패했다. `m=4,t=2`는 1,200초 제한에도 끝나지 않았다. 변수별 monomial 조합이 빠르게 늘어나는 탓에 강한 파라미터를 256개 edge 후보에 적용할 수 없었다.

두 edge nibble을 먼저 고정해 내부 다섯 구간 `[84,58,69,87,46]`만 변수로 둔 exact 5변수 모델도 시험했다. `m=2,t=1`은 256개 edge 후보를 10.5초에 모두 훑었지만 factor가 없었고, `m=3,t=1`은 후보 하나만 실행해도 300초 제한에 걸렸다. 낮은 차수는 너무 약하고 한 단계만 올려도 비용이 폭증했으므로, known-bit 섬을 전부 보존하는 exact 모델은 이 인스턴스에서 실용적인 균형점을 만들지 못했다. 이 `no-factor`와 timeout은 격자 휴리스틱의 관찰이지 `UNSAT` 증명이 아니다.

#### 얕은 grouped Herrmann--May

변수 수를 줄이기 위해 내부 known-bit gap까지 미지수에 포함시킨 grouped 2변수 모델을 시험했다. 첫 분할은 `[265,769)` 504비트와 `[784,830)` 46비트, 둘째 분할은 `[265,349)` 84비트와 `[362,830)` 468비트였다. 한 분할의 `m=1..8,t=1..2` 격자는 `256×16=4,096`개 작업이었고, `m=10,t=1..2`도 512개 작업을 추가했지만 factor가 없었다. `m=14`에서는 오답 edge 표본 하나에도 73∼106초가 걸렸고 `m=16`은 전체 sweep이 비현실적이었다.

이 결과의 교훈은 grouping 자체를 버리는 것이 아니라 두 변수의 크기를 더 균형 있게 잡고 강한 격자를 한 번 감축해야 한다는 것이었다. 최종 선택인 `[265,420)` 155비트와 `[600,830)` 230비트는 위 두 극단적 분할보다 균형이 좋았고, 얕은 sweep 대신 `m=17,t=5`를 사용했다.

#### cuso mixed-shape 탐색의 보류

cuso에는 grouped `S0=[155,230]`, exact `S1=[84,58,69,87,46]`, mixed `S2=[84,58,230]`와 `S3=[155,69,87,46]`, 그리고 하위 600비트를 부분 고정한 `S4`를 넣는 설계를 만들었다. 목적은 변수 수를 줄이는 이득과 known-bit 제약을 보존하는 이득을 같은 실행기에서 비교하는 것이었다.

다만 이 트랙은 외부 실행 환경과 root extraction을 planted/toy 인스턴스로 먼저 검증하는 soundness gate를 통과한 완료 sweep까지 진행하지 못했다. 따라서 cuso에 대해서는 “정수 관계가 없었다”거나 “수학적으로 root가 없다”는 결론을 기록하지 않는다. 실행 결과가 검증되지 않은 설계는 hard clause는 물론 soft `no-root`로도 사용하지 않고 보류했다.

#### 한 변수 two-sided `p` window

알려진 하위·상위 부분 사이의 모든 비트를 하나의 연속 변수로 두면 단변수 공격을 쓸 수 있지만, 내부 known-bit 섬을 버리는 만큼 근의 상한이 커진다. `[362,830)`을 468비트 변수로 둔 모델은 첫 선택 후보가 120초를 넘겼고, `[265,769)`의 504비트 gap 모델도 상위 후보가 90초 제한에 걸렸다. 범위를 `[420,830)`의 410비트로 줄인 변형조차 후보당 약 60초가 필요했다.

단변수라는 단순함보다 410∼504비트라는 root bound가 더 큰 병목이었다. 일부 후보의 timeout은 그 window에 근이 없다는 증명이 아니므로, 넓은 candidate oracle이나 SAT clause 생성기로 사용할 수 없었다.

#### residual partial-`p` 격자

선행 점수로 외부 비트를 고정한 뒤 `[420,830)` 안의 실제 미지 구간 `[600,669)`, `[682,769)`, `[784,830)`만 남기면 크기는 `69+87+46=202`비트가 된다. 이 세 변수를 대상으로 32개 후보에서 `m=2..4,t=1..4`를 시험했지만 factor가 없었고, 그중 `m=4,t=1`은 전부 timeout이었다. 이어 128개 후보의 `m=2..3,t=1..4`와 별도 128개 후보의 `m=4,t=2..4`도 factor를 찾지 못했다.

다른 residual `[58,69,87]` 분할의 상위 8개 후보를 `m=2..3,t=1..2`로 검사한 실행은 235.77초 동안 `no-factor` 30건과 오류 2건으로 끝났다. 최상위 한 후보의 `m=4,t=1` 및 `m=4..5,t=2..3`도 factor가 없었고, `m=6..8`은 비용 때문에 진행하지 않았다. 이 방식은 선행 ranker가 정답 근처를 골라 준다는 가정에 민감했지만, 그 순위 신호가 검증되지 않아 넓은 탐색보다 선택 편향만 커졌다.

#### folded `p/q` Coron 격자

`p`와 `q`의 중간 gap을 각각 변수로 두고 두 factor의 곱셈 관계를 직접 이용하는 Coron 계열 격자도 finalist 교차 검사로 사용했다. 양쪽 bound가 각각 456비트인 모델에서 1,024개 후보와 `k=1..4`를 444.0초에 검사했지만 factor가 없었다. `k=5`부터는 후보 하나에 수분이 필요해 broad sweep을 중단했다.

작은 `k`의 `no-factor`는 선정 후보와 해당 basis가 근을 드러내지 못했다는 뜻일 뿐, branch가 틀렸다는 증명이 아니다. 따라서 Coron 결과 역시 SAT ledger에 hard 배제로 넣지 않고 최종 후보 검사용으로만 남겼다.

#### q-gap 단변수 oracle과 직접 후보 탐색

일부 `p` 비트를 고정하면 나눗셈 관계에서 `q`의 연속된 하위 prefix와 상위 prefix를 얻을 수 있다. 둘 사이의 gap을 `x`로 두면

```text
q = q_low + 2^a*x + 2^b*q_high
```

형태의 단변수 작은 근 문제가 된다. 실행 당시에는 Sage `small_roots` backend가 설정한 Coppersmith bound와 안전 margin을 통과하면 `hard no-root`로 기록했다. 그러나 이론상 대상 소인수는 `q >= N^beta`여야 하는데 사용한 `beta=0.5`에 대해 최종 복원값은 `log_N(q)=0.4999617664`, 즉 `q^2<N`이고 `sqrt(N)`보다 약 0.0783비트 작다. 따라서 Sage와 `fpylll_linear`가 반환한 q-gap 무근 결과는 모두 휴리스틱으로만 해석해야 한다.

q-gap 456비트 직접 탐색에서 첫 128개 후보는 369.1초, 다음 256개는 784.4초가 걸렸고 총 384개가 `no-root`로 보고됐지만 factor는 없었다. 이 결과로 branch를 안전하게 닫을 수 없고, 남은 약 102비트 frontier에서 beam과 hash sampling이 덮는 비율도 극히 작았다. `no-root` 개수는 다음 후보가 factor에 가까운지도 알려 주지 않아, q-gap은 휴리스틱 점수로도 독립적인 탐색 알고리즘으로도 수렴하지 못했다.

#### q-gap SAT learned clause와 최소화

SAT 솔버가 일부 숨은 `p` 비트를 cube로 고르면 q-gap oracle으로 검사하고, 당시 `hard`로 분류한 `no-root`이면 외부 반복 loop가 그 cube를 부정하는 clause를 JSONL ledger에 기록해 다음 SAT 호출에서 읽었다. Ajani--Bright의 in-solver callback과 목적은 같지만 결합 위치는 다르다. 대표적인 407∼408비트 gap에서 `epsilon=0.02`의 margin은 62.04비트였고, `epsilon=0.04`로 조정해도 21.08비트로 8비트 안전 기준을 넘었다. 이 조정으로 base oracle은 약 21.6초에서 1.5초, 한 cube의 drop 검증은 약 493초에서 12.8초로 줄었지만, 위 `q >= N^beta` 전제 부족은 해소되지 않았다.

긴 clause를 줄이려면 제거할 비트의 모든 completion을 다시 검사했다. 양끝 4비트씩을 제거한 cumulative 검사는 `256/256` completion에서 oracle의 `no-root`를 확인해 138개 선택 비트에서 8비트를 뺀 130-literal clause를 만들었다. 별도의 `150:4 + 265:84 + 798:32 + 920:4` 124-literal high32 cube에서는 `265:8 + 273:8` union을 128개 shard로 나눠 `65,536/65,536` completion을 약 7시간 규모로 검사했고, 16비트를 뺀 108-literal clause 하나를 얻었다. 전수검사는 모든 completion이 같은 oracle 결과였다는 점만 보장하며, oracle의 beta 전제를 복구하지는 않는다. 따라서 두 clause 모두 수학적으로 sound한 no-good이 아니라 비용이 큰 휴리스틱 clause다.

후속 x7 집중 탐색은 432개 JSONL ledger와 `hard`로 표기된 q-gap `no-root` cube row 43,961개를 축적하고도 factor를 찾지 못했다. 이 field 이름은 당시 분류를 보존하지만, 현재 writeup에서는 위 이유로 전부 휴리스틱으로 해석한다. ledger가 커질수록 다음 SAT 모델을 고르는 비용도 증가했고, 정답 방향을 나타내는 목적 함수도 없어 완결된 탐색으로 이어지지 않았다.

#### low600 `p`-Coppersmith clause

`[150,154)`, `[265,349)`, `[362,420)`을 고정하면 `p[0..600)`이 완전히 알려져

```text
p = p0 + 2^600*x,  0 <= x < 2^424
```

인 단변수 문제가 된다. 이 oracle은 큰 소인수 `p`를 대상으로 하고 최종 복원값에서 `p^2>N`이므로 `beta=0.5`의 divisor 조건을 만족한다. Sage `small_roots` backend의 `low_bits=600`, `epsilon=0.02` 실행에서 effective bound는 470.04비트, 실제 미지 상한은 424비트, margin은 46.04비트여서 hard-clause gate를 통과했다. `[150,154)`를 clause에서 제거하는 검사는 `16/16` completion을 확인해 142-literal clause를 만들었다. 여기에 `[265,269)`까지 함께 제거한 검사는 `256/256` completion, 273회 oracle 호출, 약 451초를 써서 138-literal clause를 얻었다.

문제는 검증 한 건의 비용에 비해 닫히는 공간이 작다는 점이었다. 후속 cumulative 실행은 기존 clause를 읽은 뒤 첫 cube row도 쓰지 못한 채 약 5.5시간 정체되어 중단됐고, 이 불완전 로그는 증거로 사용하지 않았다. 이미 얻은 clause는 위 Sage backend·bound·margin·completion 조건 아래에서는 sound하지만 146비트 cube 공간을 충분히 덮거나 정답 쪽으로 탐색을 유도하지 못했다.

#### SAT ranker와 다양성 샘플링

q-gap과 low600 oracle 앞단에서 deep-prefix 점수, 부분곱 점수, guarded cycle, projection novelty, compacted ledger를 조합해 후보 순서를 개선하려 했다. 그러나 SAT는 긴 clause 아래에서도 비슷한 국소 basin의 모델을 반복해 반환했다. 전체 ledger 9,579개 clause, 1,319,382 literals를 읽은 ranker는 후보당 250ms 예산에서 `UNKNOWN`만 냈고, 4,096-pair Z3 ranker도 약 6분 동안 CPU-bound 상태라 중단했다.

projection novelty sampling은 중복된 projection을 줄이고 더 넓은 모양을 방문하는 데는 성공했지만, 그 다양성이 factor일 확률과 상관된다는 근거는 없었다. 즉 “이미 보지 않은 후보”는 만들었어도 “정답에 가까운 후보”를 골라 주지는 못했다.

#### Jochemsz--May low-lift 구현

12항의 2차 다변수 다항식을 다루는 Jochemsz--May 형태도 `Wbits=1591` 설정으로 시험했다. 오답 edge branch에서 `m=1`과 `m=2`는 `crypto-attacks`의 기본 resultant root extraction 단계에서 `IndexError`로 끝났다. 확장 설정 `ext_u2`와 `ext_b`는 각각 57.5초와 85.8초를 사용한 뒤 같은 오류가 났다.

이는 격자가 근을 갖지 않는다는 결과가 아니라 구현·추출 경로가 검증된 후보를 내지 못한 실패다. planted 회귀 테스트로 root extraction을 먼저 검증하지 않는 한 탐색 결과나 branch 배제 증거로 사용할 수 없어 진단 경로로만 남겼다.

정리하면 exact SMT가 `UNSAT`을, CP-SAT가 `INFEASIBLE`을 반환했다면 hard 배제에 쓸 수 있었지만 실제 실행은 모두 `UNKNOWN`이었다. 실제 hard 배제로 남길 수 있는 것은 `p^2>N`, Sage backend, bound·margin gate와 모든 completion 검사를 통과한 low600 `no-root`뿐이다. q-gap은 `q^2<N`인데 `beta=0.5`를 사용했으므로 휴리스틱이며, `SAT` prefix, timeout, 완전성 검증이 없는 다변수 격자의 `no-factor`도 branch를 닫지 못했다. 여러 실패가 공통으로 가리킨 방향은 양끝 nibble만 전수조사하고, 내부 known-bit 제약을 완화해 나머지를 155비트와 230비트의 균형 잡힌 두 변수로 묶은 뒤, 후보마다 약한 탐색을 반복하는 대신 `m=17,t=5`의 강한 HM 격자를 쓰는 것이었다.

## 최종 공격 상세

### 1. 256개 edge 후보

양끝의 4비트 구간을 하나의 후보 번호로 묶는다.

```text
low  = p[150..153]
high = p[920..923]
cid  = (high << 4) | low
```

따라서 edge 후보는 `0..255`의 256개뿐이다. 한 후보를 고정한 뒤 `265..419`와 `600..829`를 각각 연속 정수 `x`, `y`로 둔다. 두 블록 안에 이미 알려진 비트도 있지만, 그 제약을 잠시 버리면 변수 수를 크게 줄일 수 있다.

```text
p = C + 2^265*x + 2^600*y
0 <= x < 2^155
0 <= y < 2^230
```

여기서 `C`는 해당 후보의 두 edge nibble과 두 연속 블록 밖의 알려진 비트를
합친 상수다. 내부 known-bit 조건을 완화한 뒤에도 실제 `p`에 대응하는
`(x0,y0)`는 위 탐색 영역 안에 남는다. 이는 실제 근을 모델에서 제거하지
않았다는 뜻일 뿐, 뒤의 격자 감축·12개 행 선택·resultant 절차가 모든 근을
반드시 찾는다는 뜻은 아니다.

### 2. 이변수 Herrmann--May 격자

최종 solver는 `A = 2^265`, `B = 2^600`으로 놓고, `A`의 역원을 곱해 다음처럼 `x`에 대해 monic인 다항식을 만든다.

```text
f(x, y) = x + (B*A^-1 mod N)y + (C*A^-1 mod N)  (mod N)
```

실제 근 `(x0, y0)`에서는 `C + Ax0 + By0 = p`이고 `p | N`이므로 `f(x0, y0) = 0 mod p`다.
복원값은 `p ≈ N^0.500038`인 1024비트 divisor이고, 실제 변수 크기는
`bitlen(x0)=155`, `bitlen(y0)=228`이다. 따라서 선언한
`X=2^155`, `Y=2^230` 안에 각각 0비트와 2비트의 여유로 들어온다.

`m=17`, `t=5`에서 다음과 같은 triangular shift들을 사용한다.

```text
y^j * f(x,y)^k * N^max(t-k, 0),  k+j <= m
```

전체 차원은 다음과 같다.

```text
(m+1)(m+2)/2 = 18*19/2 = 171
```

실제 근에서 `f^k`는 `p^k`의 배수이고 `N^(t-k)`는
`p^(t-k)`의 배수다. 따라서 `k<t`인 행은 `p^t`의 배수이고, `k>=t`인
행도 최소 `p^t`의 배수다. 감축 후 스케일을 되돌린 다항식 `g`에 대해

```text
||g(xX,yY)의 계수||_1 < p^t
```

이면 `|g(x0,y0)| < p^t`이면서 동시에 `p^t | g(x0,y0)`이므로
`g(x0,y0)=0`인 정수 관계가 된다.

계수는 해당 `N` 거듭제곱을 기준으로 중앙 잉여값에 가깝게 바꾸고, monomial `x^i y^j` 열은 `X^i Y^j`로 스케일한다. 여기서 `X=2^155`, `Y=2^230`이다. 이렇게 만든 상삼각 형태의 171차원 격자를 목표 RHF `1.15`로 FLATTER에서 감축했다.

삼각 basis의 대각을 직접 곱하면 이 구현의 determinant는

```text
det(L) = X^969 * Y^969 * N^250
```

이다. 171차원에서 `log2(det(L)^(1/171)) ≈ 5175.58`이고, 목표 RHF
`1.15`를 단순 적용한 예상치는 약 5210.06비트다. 반면
`log2(p^t) ≈ 5119.99`이므로 determinant 예상치만으로 성공을 보장할 수는
없다. 실제 `cid=155` 감축에서 선택한 12개 행의 scaled L1 bit length는
`5107..5109`였고 `p^t`보다 약 11비트 이상 작았다. solver는 복원한
`(x0,y0)`를 12개 다항식에 정확한 정수로 대입해 평가값이 모두 0인지
추가로 검사한다.

최종 파라미터는 다음과 같다.

```text
m=17, t=5, dimension=171
leading variable=x
centered coefficients=true
target RHF=1.15
```

낮은 파라미터는 사전 sweep에서 factor를 내지 못했고, `m=14`도 오답
표본 하나에 73~106초가 들면서 성공 관계를 만들지 못했다. `m=17,t=5`는
determinant 식에서 자동으로 도출된 보장값이 아니라, 위 실제 L1 gate와
planted/modular self-test를 통과한 성공 파라미터다.

### 3. 결과식과 CRT로 근 복원

감축된 행 중 L1 norm이 작은 12개를 보조 다항식으로 선택한다. 큰 정수 위에서 한 번에 결과식을 계산하는 대신 약 30비트 소수체에서 다음 과정을 반복한다.

1. 보조 다항식 쌍의 resultant로 `x`를 제거한다.
2. 여러 resultant의 GCD를 구해 `y`에 대한 일차식을 얻는다.
3. `y`를 대입한 보조 다항식들의 GCD로 `x`를 얻는다.
4. 복원한 `(x, y)`가 선택한 모든 보조 다항식을 만족하는지 확인한다.
5. 서로 다른 소수에서 얻은 근을 CRT로 합친다.

오답 edge 후보는 대개 첫 소수 `1,000,000,007`에서 resultant GCD가 1이 되어 빠르게 탈락한다. 정답 후보에서는 8개 소수의 공통근이 일치했고, CRT modulus가 약 240비트가 되어 `Y`를 넘었을 때 정수 근과 `p`가 유일하게 복원됐다.

여기서 L1 norm이 작은 12개 행의 선택, 일부 다항식 쌍의 resultant,
일차 GCD만 처리하는 root extraction, 최대 10개 소수라는 제한은 모두
heuristic이다. 후보를 얻었을 때 `candidate | N`을 검사하므로 잘못된
factor를 채택하지는 않지만, 실패한 branch에 근이 없음을 증명하지도
않는다. CRT 종료 조건은 구현에서도 `modulus > max(X,Y)`로 검사한다.

```text
cid  = 155 = 0x9b
low  = 0xb
high = 0x9
```

### 4. 복원 결과

두 소인수는 다음과 같다.

```text
p = 0xffa360d46885c534d186538179633fafc2c0548a2e24a2c1c878569f522939e38ff75ead1bcd442a834974a52e3ac66c1bc2ee00d63e2de4c436d2ca740a624699e1a1af94045c63261323cb723a7ba1b3c00bbbb6a4e534c11469e73ddbb2e50b0bc2461fcbac0726360c2c0ac9450a9a892cbf1d98ceee48827591ccc593c9
q = 0xe557fa8670389cb60c84416a65742a74fd11ed33b1631f787e92b90887b5391dacba00a386911bf8a8fbd57430b9b26e455329405ffe289e20616fe3b5562ea9b533f8f8db94bb8dcd280a6af056108e176008d3655428ad0ac6396318ba0f6efe496eac3f8585675bfed67081e0c518be5685e4daf7060abe1c58b73cc5f1e9
```

이후 표준 RSA 개인 지수를 계산해 복호화한다.

```python
phi = (p - 1) * (q - 1)
d = pow(65537, -1, phi)
m = pow(ct, d, N)
```

최종 평문은 다음과 같다.

```text
FLAG{d1rty_b1t_l34k_c0pp3rsm1th_m33ts_str4t3gy}
```

### 격자 공격 재실행

검증한 환경은 Debian 12 계열, GCC 12.2.0, FLINT 2.9.0, GMP 6.2.1,
OpenBLAS 0.3.21, fplll 5.4.4, MPFR 4.2.0이며 FLATTER는 다음 revision으로
고정했다.

```text
FLATTER d2b8026f29b4a69e987b15d4b240f8a5053275d3
```

FLATTER를 해당 revision에서 CMake Release build한 뒤 설치 prefix를
`$FLATTER_PREFIX`라고 하면 solver는 다음처럼 빌드한다. commit 문자열도
binary stdout에 들어가므로 다른 revision으로 빌드했다면 macro를 함께
바꿔야 한다.

```bash
g++ -O3 -std=c++17 \
  -DFLATTER_GIT_COMMIT='"d2b8026f29b4a69e987b15d4b240f8a5053275d3"' \
  -I"$FLATTER_PREFIX/include" \
  solutions/solve_07_grouped_hm_flatter.cpp \
  -L"$FLATTER_PREFIX/lib" -Wl,-rpath,"$FLATTER_PREFIX/lib" \
  -lflatter -lflint -lgmpxx -lgmp -lopenblas -pthread \
  -o /tmp/solve_07_grouped_hm_flatter

/tmp/solve_07_grouped_hm_flatter --modular-selftest

OPENBLAS_NUM_THREADS=1 /tmp/solve_07_grouped_hm_flatter \
  --challenge --cid 155 --m 17 --t 5 --rhf 1.15 \
  --threads 4 --lead x --centered
```

마지막 명령은 이미 알려진 정답 branch `cid=155`를 재실행해 복원값을
검증하며, 위 환경의 두 실행에서는 감축에 약 62~73초가 걸렸다. 정답 branch를 모르는
상태에서 256개를 실제로 찾는 blind scan은 별도 runner로 실행한다.

```bash
python3 solutions/run_07_grouped_hm_scan.py \
  /tmp/solve_07_grouped_hm_flatter \
  --output-dir /tmp/challenge07-full-scan \
  --jobs 2 --solver-threads 4 \
  --flatter-commit d2b8026f29b4a69e987b15d4b240f8a5053275d3
```

runner는 `0..255`를 숫자 순서로 모두 계획하고 정답 `cid`를 입력이나 실행
순서에 seed하지 않는다. 각 process 안의 FLATTER worker는 4개,
동시 process는 2개, BLAS thread는 1개로 고정된다. 각 `cid`의 return code,
wall time, stdout SHA-256, factor·mask 검증 결과를 개별 JSON에 기록하고,
binary/source SHA-256, compiler, `ldd`, 파라미터와 성공 후보 수를
`summary.json`에 모은다. `returncode=2`는 `no_recovery`일 뿐 무근 증명이
아니다. timeout/error가 있거나 검증된 서로 다른 factor가 정확히 하나가
아니면 full scan은 실패 코드로 끝난다.

전체 256개 scan은 계산 비용이 커 이 저장소 수정 세션에서 다시 실행하지
않았다. 대신 pinned FLATTER를 처음부터 빌드해 modular self-test,
171차원 basis build, `cid=155` 복원과 12개 정수 다항식 평가를 다시
실행했다. blind runner에는 실행하지 않은 결과 로그를 포함하거나
`successful candidates=1`을 미리 기록하지 않았다.

## 참고 자료와 활용

- [Ronald Rivest, Adi Shamir, and Leonard Adleman, *A Method for Obtaining Digital Signatures and Public-Key Cryptosystems* (Communications of the ACM, 1978)](https://people.csail.mit.edu/rivest/pubs/RSA78.pdf) — `352비트 전수조사`의 후보 검증식 `p | N`과 `복원 결과`의 RSA 구조에 대한 원전이다. 이 인용은 순진한 열거 비용의 기준일 뿐, 최선의 공격에도 `2^352`가 필요하다는 하한을 뜻하지 않는다.
- [Don Coppersmith, *Small solutions to polynomial equations, and low exponent RSA vulnerabilities* (Journal of Cryptology, 1997)](https://research.ibm.com/publications/small-solutions-to-polynomial-equations-and-low-exponent-rsa-vulnerabilities) — `배경지식`에서 작은 modular root를 격자로 정수 근으로 끌어올리고, 알려진 소인수 비트로 RSA를 인수분해할 수 있다는 출발점을 설명하는 데 사용했다.
- [Nick Howgrave-Graham, *Finding Small Roots of Univariate Modular Equations Revisited* (Cryptography and Coding, LNCS 1355, pp. 131–142, 1997)](https://doi.org/10.1007/BFb0024458) — `two-sided p`, q-gap, low600처럼 변수가 하나인 modular small-root oracle의 격자 구성과 실용적 판정 조건을 정리할 때 참고했다. 특히 q-gap의 `beta=0.5`가 작은 소인수 `q`에 맞지 않는다는 사후 경계 감사에도 사용했다.
- [Mathias Herrmann and Alexander May, *Solving Linear Equations Modulo Divisors: On Factoring Given Any Bits* (ASIACRYPT 2008)](https://www.iacr.org/archive/asiacrypt2008/53500412/53500412.pdf) — `256개 edge 후보`와 `이변수 Herrmann--May 격자`에서 미지 블록을 선형식으로 묶고 `y^j f^k N^max(t-k,0)` shift로 삼각 격자를 구성한 직접적인 이론적 근거다.
- [Jean-Sébastien Coron, *Finding Small Roots of Bivariate Integer Polynomial Equations Revisited* (EUROCRYPT 2004)](https://iacr.org/archive/eurocrypt2004/30270487/bivariate.pdf) — `folded p/q Coron 격자`에서 두 개의 bounded gap을 이변수 정수 다항식의 작은 근으로 다루는 실험 방향을 잡는 데 참고했다.
- [Ellen Jochemsz and Alexander May, *A Strategy for Finding Roots of Multivariate Polynomials with New Applications in Attacking RSA Variants* (ASIACRYPT 2006)](https://www.iacr.org/archive/asiacrypt2006/42840270/42840270.pdf) — exact·mixed 다변수 모델의 shift 선택과 `Jochemsz--May low-lift 구현`을 설계할 때 참고했으며, 구현 오류를 수학적 no-root로 해석하지 않은 이유와도 관련된다.
- [Leonardo de Moura and Nikolaj Bjørner, *Z3: An Efficient SMT Solver* (TACAS 2008)](https://doi.org/10.1007/978-3-540-78800-3_24) — `전체 2048비트 곱셈 SMT`의 bit-vector 제약을 푼 solver의 기반 문헌이다. 이 문제에서의 timeout/`UNKNOWN`은 논문이나 SMT 접근 전체의 부정적 결과가 아니다.
- [Laurent Perron, Frédéric Didier, and Steven Gay, *The CP-SAT-LP Solver* (CP 2023)](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.CP.2023.3) — `하위 곱셈만 정확히 표현한 CP-SAT`에서 Boolean·정수 carry 제약을 함께 푼 solver 계열의 문헌이다.
- [Nadia Heninger and Hovav Shacham, *Reconstructing RSA Private Keys from Random Key Bits* (CRYPTO 2009)](https://hovav.net/ucsd/papers/hs09.html) — `Hensel-prefix 분기`의 mod `2^k` 해를 한 비트씩 lifting하는 branch-and-prune와 직접 관련된다. 다만 논문의 random multi-component leakage 조건은 이 문제의 p-only block mask와 다르므로 성공 bound를 그대로 적용하지 않았다.
- [Yameen Ajani and Curtis Bright, *SAT and Lattice Reduction for Integer Factorization* (ISSAC 2024, pp. 391–399)](https://cs.curtisbright.com/reports/issac-fact.pdf) ([DOI](https://doi.org/10.1145/3666000.3669712)) — partial bit assignment를 SAT가 만들고 Coppersmith oracle이 확장 가능성을 검사하는 q-gap/low600 하이브리드의 가장 직접적인 선행 연구다. 논문은 programmatic in-solver callback을 사용하지만 이 저장소는 외부 반복 loop와 JSONL ledger를 사용하며, q-gap의 beta 전제 부족 때문에 그쪽 clause는 휴리스틱으로만 남겼다.
- [Alexander Nadel, *Generating Diverse Solutions in SAT* (SAT 2011, LNCS 6695, pp. 287–301)](https://satassociation.org/proceedings/SAT11/papers/SAT2011-page-281.pdf) ([DOI](https://doi.org/10.1007/978-3-642-21581-0_23)) — `SAT ranker와 다양성 샘플링`에서 서로 다른 모델을 생성하려는 동기를 제공했다. projection-frequency novelty 자체는 프로젝트 고유 구현이며, 원 논문의 다양성 목적을 factor 정답 확률에 대한 보장으로 해석하지 않았다.
- [Keegan Ryan, *Solving Multivariate Coppersmith Problems with Known Moduli* (EUROCRYPT 2025)](https://eprint.iacr.org/2024/1577.pdf) — Gröbner basis와 graph heuristic으로 multivariate shift를 고르는 cuso의 이론과 설계를 확인했다. `cuso mixed-shape`의 S0∼S4 변수 분할은 논문에 있는 고정 분할이 아니라 이 문제를 위해 만든 입력 모델이다.
- [Keegan Ryan, *Solving Multivariate Coppersmith Problems with Known Moduli* 구현 자료 (EUROCRYPT 2025 Artifact)](https://artifacts.iacr.org/eurocrypt/2025/a13/readme.html) — cuso가 bounded multivariate root 문제의 shift를 자동 구성하고 graph 기반으로 격자 크기를 줄이는 도구라는 점을 확인하고, `cuso mixed-shape 탐색의 보류`에 적은 S0∼S4 설계를 준비할 때 참고했다.
- [jvdsn/crypto-attacks](https://github.com/jvdsn/crypto-attacks) — partial-`p`, folded Coron과 Jochemsz--May 실험의 격자·resultant root extraction 구현으로 사용했다. 탐색 기록에 checkout commit이 남아 있지 않으므로 `IndexError` 결과는 저장소와 기본 resultant 경로까지만 특정하며 특정 revision에 대한 재현 주장으로 확대하지 않는다.
- [SageMath `small_roots` 문서](https://doc.sagemath.org/html/en/reference/polynomial_rings/sage/rings/polynomial/polynomial_modn_dense_ntl.html#sage.rings.polynomial.polynomial_modn_dense_ntl.small_roots) — `beta`가 대상 divisor `b >= N^beta`의 하한이라는 API 조건을 확인했다. 이 조건과 복원된 `p,q`를 대조해 q-gap 결과는 휴리스틱으로 낮추고 low600 결과만 hard gate 대상으로 유지했다.
- [RFC 8017, *PKCS #1: RSA Cryptography Specifications Version 2.2*](https://www.rfc-editor.org/rfc/rfc8017.html#section-5.1) — `복원 결과`와 `검증`에서 사용한 RSA 공개·개인 지수 연산 및 복호화/재암호화 primitive의 기준이며, 이 문제는 별도 padding 없이 raw RSA primitive를 적용한다.
- [FLATTER 공식 프로젝트](https://github.com/keeganryan/flatter) — `이변수 Herrmann--May 격자`와 `격자 공격 재실행`의 171차원 basis 감축, 목표 RHF 옵션 및 빌드 방법을 확인하는 구현 자료로 사용했다.
- [FLINT 공식 `nmod_poly` 문서](https://flintlib.org/doc/nmod_poly.html) — `결과식과 CRT로 근 복원`에서 소수체 위 resultant와 polynomial GCD를 계산하는 API 및 연산 의미를 확인하는 데 사용했다.
