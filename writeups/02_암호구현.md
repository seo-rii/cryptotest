# 2. 암호구현 - 256비트 permutation 복원과 최적화

## 문제와 제출 목표

제공된 `contest.c`는 네 개의 64비트 word로 이루어진 256비트 상태에 다음 연산을 적용한다.

- word별 64비트 rotate-left
- 네 word와 상수의 XOR
- 32바이트 shuffle
- word별 modulo `2^64` 덧셈

1라운드의 연산 순서와 서로 다른 네 rotation 값을 복원하고, 같은 라운드를 20회 수행하는 코드를 완성해야 한다. 1라운드 벡터 1,000개와 20라운드 벡터를 모두 통과해야 하며 20라운드 반복 실행 시간이 성능 평가 대상이다.

최종 제출물은 다음 두 파일이다.

- `submissions/02/contest.c`: 제공된 테스트·타이밍 골격을 유지한 최적화 코드
- `submissions/02/report.pdf`: 분석, 구현, 검증, 벤치마크 보고서

## 구조와 rotation 복원

### 역연산

각 단계는 쉽게 되돌릴 수 있다.

- 덧셈의 역은 같은 상수의 뺄셈이다.
- `shuffle_map[i] = 31-i`인 32바이트 reversal은 자기 자신의 역이다.
- XOR은 같은 상수를 다시 XOR하면 된다.
- rotate 값은 허용 범위 `1..63`을 검사할 수 있다.

출력 `out`에 역연산을 적용하면 rotate 직후 값이 나온다.

```text
t0 = out - constants1              (mod 2^64, word별)
t1 = reverse_all_32_bytes(t0)
t2 = t1 xor constants2
```

각 word `i`에서 다음 조건을 만족하는 `r_i`를 찾는다.

```text
ROTL64(input[i], r_i) == t2[i]
```

`solutions/solve_02_permutation.py`는 첫 벡터 하나에 의존하지 않고 1,000개 벡터에서 얻은 후보 집합을 모두 교차한다. 각 word에 정확히 하나만 남는다.

```text
rot = {43, 7, 29, 14}
```

복원된 1라운드 순서는 다음과 같다.

```text
rotate -> XOR -> reverse-byte shuffle -> add
```

## 기준 구현

기준 구현은 제공된 네 서브 연산을 그대로 이어 붙인다.

```c
rotate_words_left_64wise(state, rot);
xor_constants_256wise(state, constants2);
shuffle_bytes_256(state, shuffle_map);
add_constants_64wise(state, constants1);
```

20라운드는 이 함수를 20번 반복한다. 이 구현은 임의의 rotation 배열과 shuffle map을 처리하지만, 매 라운드 32바이트 임시 배열 두 개와 map 기반 byte load/store를 사용한다.

## 최적화 구현

### 32바이트 shuffle의 대수적 축약

문제의 map은 임의 permutation이 아니라 32바이트 전체 reversal이다. 네 word를 `x0, x1, x2, x3`이라 하면 결과는 다음과 같다.

```text
reverse32(x0, x1, x2, x3)
    = (BSWAP64(x3), BSWAP64(x2), BSWAP64(x1), BSWAP64(x0))
```

따라서 32회의 indexed byte copy를 네 번의 64비트 byte-swap으로 바꿀 수 있다. GCC와 Clang에서는 `__builtin_bswap64`를 사용하며, 다른 C 컴파일러를 위한 shift/mask fallback도 포함했다.

### 고정 rotation 특수화와 register 유지

복원한 rotation과 word reversal을 결합하면 한 라운드는 바로 다음 식이 된다.

```text
y0 = BSWAP64(ROTL64(x3, 14) xor C2[3]) + C1[0]
y1 = BSWAP64(ROTL64(x2, 29) xor C2[2]) + C1[1]
y2 = BSWAP64(ROTL64(x1,  7) xor C2[1]) + C1[2]
y3 = BSWAP64(ROTL64(x0, 43) xor C2[0]) + C1[3]
```

rotation이 compile-time constant이므로 compiler가 variable-shift 대신 즉시값 shift/rotate를 선택할 수 있다. 20라운드 함수에서는 네 word를 local scalar에 유지해 매 라운드의 임시 byte 배열과 불필요한 memory traffic을 제거한다. 최종 코드는 x86 전용 AVX intrinsic에 의존하지 않는 portable scalar C다.

AVX2도 사용할 수 있지만 상태가 256비트 하나뿐이고 네 lane의 rotation 값이 모두 다르며 라운드 사이에 직렬 의존성이 있다. 이 경우 SIMD setup과 lane별 shift 조합의 이득이 확실하지 않아, 제출 환경 이외에서도 그대로 컴파일되는 scalar 특수화를 선택했다.

## 정확성 검증

`solutions/solve_02_permutation.c`에는 제공 코드와 같은 generic reference와 최적화 함수를 함께 넣었다. 다음 검사를 모두 수행한다.

1. 제공된 1라운드 벡터 1,000개에서 reference와 optimized 결과를 각각 정답과 비교
2. 제공된 20라운드 벡터에서 두 구현을 각각 정답과 비교
3. 고정 seed의 xorshift64로 만든 100,000개 상태에서 1라운드와 20라운드 differential test
4. 실제 제출용 `contest.c`를 제공된 원본 testvector 파일 옆에서 실행

## 재현 가능한 벤치마크

다음 명령은 임시 디렉터리에 testvector를 추출하고, reference와 optimized 구현을 같은 명령으로 컴파일한 뒤 정확성 검사와 벤치마크를 연속 수행한다.

```bash
python3 solutions/benchmark_02_permutation.py \
  --iterations 1000000 --repeats 9 --random-cases 100000
```

측정 조건:

```text
host       : Linux x86-64 VM, AMD EPYC 7B12
compiler   : gcc 12.2.0
flags      : -O3 -std=c11 -Wall -Wextra -Wpedantic -DNDEBUG
timer      : clock_gettime(CLOCK_MONOTONIC)
workload   : sample마다 각 구현의 20-round 호출 1,000,000회
samples    : 9회, 실행 순서를 sample마다 교대
reporting  : 각 구현의 wall-clock sample 중앙값
-march     : native 미사용
```

2026-07-17 이 호스트에서 얻은 실제 결과:

| 구현 | 20라운드 1회 중앙값 | 상대 성능 |
|---|---:|---:|
| generic reference | 834.819 ns | 1.00x |
| optimized scalar | 44.101 ns | 18.930x |

최종 제출용 원본 timing harness를 별도로 한 번 실행했을 때 optimized 함수는 `0.049428 us`/20-round였다. 이 값은 단일 run이므로 위 표의 교대 9회 중앙값을 대표 결과로 사용한다.

이 수치는 현재 VM에서 reference 대비 개선을 측정한 값이다. 최종 평가 CPU는 Intel Core Ultra 7 255H이고 compiler도 GCC 13.3.0이므로 절대 시간과 speedup은 달라질 수 있다. `--native`를 지정하지 않은 결과라서 AVX2 지원 여부와 무관하게 재현할 수 있다.

## 결론

복원한 구조는 `rotate -> XOR -> reverse -> add`, rotation은 `{43, 7, 29, 14}`다. 모든 제공 벡터와 100,000개 differential case를 통과했다. 최적화의 핵심은 일반적인 32-byte map loop를 word reversal과 `BSWAP64`로 치환하고 고정 rotation을 상수화한 것이다.
